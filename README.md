# OpenClaw Access Broker

**Временный доступ к SSH, API и веб-админкам без передачи паролей в переписку с AI-агентом.**

Access Broker — плагин для OpenClaw. Владелец открывает защищённую форму из Telegram, указывает параметры подключения и подтверждает доступ. Агент получает инструменты для работы с подключением, а не пароль или API-токен.

Текущая версия: **0.8.2**. Внутренний идентификатор плагина: `ssh-broker`.

## Для чего нужен

- Дать агенту временный доступ к файлам сайта на сервере.
- Подключить HTTPS API с Basic Auth, Bearer-токеном или API-ключом.
- Читать разрешённые страницы веб-админки после входа.
- Обращаться к локальной HTTP-панели через зашифрованное SSH-соединение.
- Отдельно разрешить неинтерактивные SSH-команды для разработки и обслуживания.
- Удалить временный доступ после завершения задачи.

Пароли вводятся в форме, а не в сообщениях. Не вставляйте реальные секреты в чат, задачи, команды или GitHub Issues.

## Поддерживаемые подключения

| Тип | Аутентификация | Возможности |
| --- | --- | --- |
| SSH / SFTP | Пароль; закреплённый SHA-256 отпечаток сервера | Файлы в разрешённых каталогах; команды при отдельном согласии |
| HTTPS API · Basic Auth | Логин и пароль в заголовке Authorization | GET, POST, PUT, PATCH, DELETE в пределах разрешённых путей |
| HTTPS API · Token | Bearer или X-API-Key | Запросы к закреплённому HTTPS origin |
| HTTPS веб-админка | POST-вход через JSON или обычную форму | Cookie-сессия и GET разрешённых страниц |
| HTTP веб-админка через SSH | Отдельное SSH-подключение и данные веб-входа | JSON/form-вход и GET панели на localhost удалённого сервера |

SSH-ключи и agent forwarding в этой версии не поддерживаются. Веб-доступ — не полноценная браузерная автоматизация: JavaScript, CAPTCHA, OAuth и многошаговый вход автоматически не обрабатываются.

## Как это работает

```text
Владелец в Telegram
    | /accesslogin -> кнопка открытия формы
    v
HTTPS-форма Access Broker
    | параметры -> проверка -> подтверждение
    v
Память процесса OpenClaw Gateway
    | временный доступ, привязанный к сессии
    v
Инструменты брокера -> SSH / HTTPS API / веб-панель
    |
    +-> агент получает результат операции, не сохранённый пароль
```

Команда возвращает кнопку типа Web App: форма может открываться внутри Telegram. Это HTTPS-форма с одноразовым билетом, а не отдельная система авторизации через Telegram Mini Apps initData. Право вызвать команду проверяет OpenClaw; самой ссылкой нужно распоряжаться как временным секретом и не пересылать её.

## Требования

- OpenClaw **2026.8.1 или новее**, согласно манифесту и package.json плагина.
- Настроенный Telegram-канал OpenClaw и право `operator.admin` для команды `/accesslogin`.
- HTTPS-адрес формы, доступный пользователю, либо установленный `cloudflared` для опционального Quick Tunnel.
- Сетевой доступ Gateway к целевому SSH-серверу или HTTPS-сервису.
- На SSH-сервере — парольная аутентификация и SFTP; для команд дополнительно POSIX `sh` и GNU `timeout`.
- Явно разрешённые оператором optional tools плагина в политике инструментов OpenClaw.

## Установка

Полный дистрибутив включает готовый `.tgz`, `install.sh`, контрольные суммы и все runtime-файлы. Пошаговая инструкция: [INSTALL.md](INSTALL.md). Скачайте [access-broker-v0.8.2-installation.zip](https://github.com/NosDorma-pixel/openclaw-access-broker/releases/download/v0.8.2/access-broker-v0.8.2-installation.zip). Откройте терминал в распакованной папке access-broker-v0.8.2-installation. Быстрый запуск: `bash install.sh --dry-run`, затем `bash install.sh`. Это онлайн-установка зависимостей, не автономный offline-комплект.

### Из локального архива

Используйте доверенный npm-pack архив плагина. Из корня полного дистрибутива или полного клона репозитория:

```bash
openclaw plugins install npm-pack:./releases/local-openclaw-ssh-broker-0.8.2.tgz
```

### Из локального каталога

Если пакет уже собран и содержит `dist/index.js` и `openclaw.plugin.json`:

```bash
openclaw plugins install ./openclaw-access-broker
```

Команды установки приведены по документации OpenClaw. Подтвердите доверие источнику, если установщик запросит его. Публикации в npm registry нет; используйте локальный npm-pack. Установка из полного клона описана в INSTALL.md.

После установки настройте плагин. Если OpenClaw оставил его выключенным до настройки, включите его:

```bash
openclaw plugins enable ssh-broker
openclaw plugins list --json
```

Не заменяйте существующую конфигурацию целиком. Сохраните остальные плагины, правила allow/deny и параметры Gateway.

## Минимальная настройка

Фрагмент ниже — **значение `plugins.entries["ssh-broker"].config`**, а не полный конфигурационный файл OpenClaw. Замените демонстрационный HTTPS-домен своим:

```json
{
  "allowDynamicAccounts": true,
  "publicBaseUrl": "https://access.example.com",
  "credentialTtlSeconds": 86400,
  "ticketTtlSeconds": 600,
  "accounts": {}
}
```

- `allowDynamicAccounts` разрешает добавлять SSH-подключения через форму; по умолчанию выключен.
- `publicBaseUrl` — HTTPS origin без пути, query и fragment. Направьте его на HTTP listener Gateway с корректным TLS и proxy-настройками.
- Вместо постоянного адреса можно включить `quickTunnel.enabled` и задать `quickTunnel.executable` — абсолютный путь к установленному `cloudflared`.
- Quick Tunnel публикует HTTP listener Gateway, а не только форму. Остальные маршруты сохраняют свою обычную авторизацию; проверьте её до включения туннеля.
- `accounts` содержит преднастроенные SSH-цели: host, port, username, hostKeySha256 и allowedRoots. Пароль в конфигурации не обязателен.

Все 18 инструментов плагина optional. Разрешайте только нужные; наличие подключения само по себе не включает инструменты. Для SSH-команд необходимы и разрешение инструмента в политике, и отдельное согласие владельца в форме.

## Быстрый старт в Telegram

1. В личном чате с ботом отправьте `/accesslogin`.
2. Откройте кнопку **«Передать доступ»**. Не публикуйте полученную ссылку.
3. Вставьте параметры в поле распознавания либо выберите тип и заполните поля вручную.
4. Проверьте адрес, пользователя, разрешённые пути и SSH-отпечаток, если применимо.
5. Подтвердите подключение и вернитесь в чат.
6. Попросите агента выполнить конкретную задачу и после работы удалить временный доступ.

Пример блока для **поля формы**, не для чата; пароль ниже — заглушка:

```text
type: ssh
host: example.com
login: site_user
password: REPLACE_IN_FORM
path: /home/site_user/public_html
```

Распознавание понимает русские и английские подписи, SSH URL/команды и типовые блоки API-доступа. Неоднозначные или неполные данные отклоняются. Вручную заполнить форму можно в том же интерфейсе.

Если SSH-порт не указан, используется 22. Если каталог не задан, после аутентификации определяется реальный домашний каталог SFTP. Неограниченный корень `/` не допускается. При первом подключении сверяйте показанный отпечаток с доверенным источником: само сканирование сервера ещё не подтверждает его подлинность.

Примеры дальнейших запросов агенту:

> Покажи доступные подключения и срок действия доступа.
>
> Прочитай README проекта в разрешённой папке, ничего не меняй.
>
> Через подключённый API получи список товаров. Не выполняй запросы на изменение.
>
> Работа закончена. Удали временный доступ к этому подключению.

## Срок действия и удаление

| Параметр | По умолчанию | Диапазон |
| --- | --- | --- |
| Билет открытия формы: ticketTtlSeconds | 10 минут | 60–1800 секунд |
| Временные credentials: credentialTtlSeconds | 24 часа | 60–604800 секунд |

Это разные сроки: истечение ссылки не означает такой же срок уже сохранённого доступа. Временные данные и cookies хранятся в памяти процесса и после истечения TTL больше недоступны операциям брокера. Перезапуск процесса Gateway теряет временные доступы; совместимая горячая перезагрузка плагина может их сохранить.

Повторное подтверждение того же ID в той же сессии заменяет данные и запускает полный TTL заново. Простое открытие формы доступ не продлевает. При замене веб-подключения прежние cookies удаляются.

Удаление через брокер убирает временную запись текущей сессии, но **не меняет пароль, не отзывает API-ключ у провайдера и не завершает гарантированно серверную веб-сессию**. При необходимости отзовите доступ также на стороне сервиса.

Преднастроенный SSH-пароль, включая поддерживаемый SecretRef, — отдельный режим: удаление временной записи не удаляет источник секрета из конфигурации. Для полностью временного сценария не задавайте постоянный пароль.

## Работа с файлами и командами

SFTP поддерживает список каталога, чтение ограниченного UTF-8 файла, замену одного точного блока с проверкой SHA-256 и резервной копией, создание файла, создание одного каталога и перенос обычного файла без перезаписи назначения.

Создание файла ограничено меньшим из 256 KiB и лимита подключения; родитель должен существовать. Перенос поддерживает бинарные файлы до 512 MiB с проверкой SHA-256; межфайловое копирование с удалением и перенос каталогов не выполняются.

Проверки путей и canonical roots ограничивают SFTP-операции; операции изменения отклоняют опасные symlink-пути. Это не OS sandbox и не защита от всех гонок с другим привилегированным процессом. Не работайте в деревьях, которые одновременно изменяет недоверенный пользователь.

Для SSH-команд отметьте **«Разрешить выполнение SSH-команд в этой сессии»** перед сохранением. Флажок по умолчанию выключен; повторный вход без него отзывает разрешение. Разрешение связано с подключением и сессией, действует до TTL, удаления или замены доступа.

**Команды имеют права SSH-пользователя. allowedRoots не ограничивает shell, а cwd задаёт только начальный каталог.** Используйте отдельного непривилегированного пользователя, не root.

Команды неинтерактивные, без stdin: таймаут 1–300 секунд, по умолчанию 120; суммарный вывод ограничен 256 KiB. Это не менеджер фоновых процессов: detached/nohup/setsid-задачи не поддерживаются. При разрыве связи результат изменения может быть неизвестен — сначала проверьте состояние, а не повторяйте команду вслепую.

Отдельный аудит диска выполняет фиксированный, ограниченный по времени и выводу read-only сценарий только для пользователя root. Он охватывает весь хост и является явным исключением из ограничения SFTP-каталогами; произвольный shell-ввод этот инструмент не принимает.

## Модель безопасности и границы

- Секреты, введённые через форму, поступают непосредственно в Gateway и не передаются в чат или параметры инструментов. Временное хранилище не записывает их в конфигурацию или файлы.
- SSH-операции сверяют закреплённый host key. Для HTTPS используются закреплённый origin и разрешённые префиксы путей; редиректы автоматически не выполняются.
- HTTP-панель доступна только на localhost SSH-сервера через туннель; публичный незашифрованный HTTP-вход не поддерживается.
- Формы используют одноразовые криптографические билеты и CSRF nonce, проверку origin, запрет кеширования и ограничительную CSP.
- Временные подключения привязаны к ключу сессии OpenClaw. Это не замена политике доступа к чату: не выдавайте чувствительные подключения в общей сессии с недоверенными участниками.
- Gateway, его оператор, процесс, reverse proxy и конечный сервис входят в доверенную среду. Защищайте память процесса, дампы, TLS-терминацию и журналы; не включайте запись тел форм и URL с билетами.
- **Результаты операций видны агенту.** Прочитанный секретный файл, ответ API или вывод команды могут содержать секреты. Маскирование точного SSH-пароля в выводе exec не является универсальной очисткой всех данных.

Брокер не заменяет password manager, secrets vault или изолированную среду выполнения. Он сокращает передачу credentials через разговор с моделью, но не делает выданные права безопасными автоматически.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Ссылка истекла или уже использована | Запросите новую через /accesslogin; не используйте старый билет |
| Нет HTTPS-адреса формы | publicBaseUrl либо настройки и доступность cloudflared |
| Команда или инструменты недоступны | Активность ssh-broker, право operator.admin и политику optional tools |
| Подключение не готово | TTL, перезапуск Gateway и совпадение текущей сессии; войдите заново |
| Путь отклонён | Разрешённые каталоги/HTTP-префиксы, canonical path и symlink-ограничения |
| SSH fingerprint не совпал | Остановитесь и независимо проверьте сервер; не принимайте новый отпечаток вслепую |
| SSH-команды запрещены | Разрешение инструмента и флажок согласия при последнем входе |
| Не хватает TTL для команды | Обновите доступ: срок должен покрывать таймаут команды и транспортный запас |
| HTTPS/TLS или адрес отклонены | Валидный сертификат, bare HTTPS origin; для HTTP-панели используйте SSH-туннель |
| Веб-панель не авторизуется | Пути и имена login-полей, JSON/form-режим, cookies; сложный browser-login может не поддерживаться |

## Разработка и участие

Этот репозиторий содержит доступный runtime JavaScript, а не оригинальный TypeScript checkout. Сценариев build/test и исходных тестов здесь нет; для TypeScript-сборки нужен оригинальный проект автора.

Для небольшого изменения проверяйте один непосредственно затронутый сценарий. Не используйте реальные credentials в тестовых фикстурах. Обработка поздних ошибок SFTP-канала и ReadStream сохранена из runtime 0.8.1. Версия 0.8.2 исправляет упаковку, метаданные и документацию; новых возможностей не добавляет.

Предложения и воспроизведения ошибок приветствуются. Указывайте версии OpenClaw и плагина, ожидаемое поведение и обезличенные шаги. Не прикладывайте пароли, cookies, API-ключи, приватные адреса или рабочие ссылки формы. Уязвимости обсуждайте с сопровождающим приватно, без публикации действующего доступа.
