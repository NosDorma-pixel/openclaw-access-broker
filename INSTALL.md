# Установка Access Broker 0.8.2

## Что находится в архиве

- `install.sh` — установщик локального пакета через официальный CLI OpenClaw.
- `releases/local-openclaw-ssh-broker-0.8.2.tgz` — готовый npm-pack, сборка TypeScript не нужна.
- `dist/*.js` — весь доступный исполняемый JavaScript-код плагина; HTML/CSS форм встроены в него. Также включены декларации и карты исходников.
- `package.json`, `openclaw.plugin.json`, README, примеры настройки и SHA256SUMS.

Это **онлайн-установка**: node_modules не включён. OpenClaw устанавливает зависимости из npm; нужны сеть и доступ к реестру. В package.json зафиксированы непосредственные runtime-зависимости ssh2 1.17.0 и typebox 1.3.16. Исходного lockfile нет, поэтому транзитивные версии не закреплены. На платформах без необязательного ускорителя ssh2 может использовать JavaScript-реализацию.

Исходные TypeScript-файлы, tsconfig и исходные тесты в установленном пакете отсутствуют. Они не восстановлены и не подменены: доступный исходный код — читаемые dist/*.js. Ссылки карт на ../src/*.ts не означают, что эти файлы включены. Для самостоятельной TypeScript-сборки нужен оригинальный checkout автора; для установки этот checkout не нужен.

## 1. Подготовить хост

Запускайте на хосте Gateway от того же непривилегированного пользователя и с тем же профилем/окружением, что и целевой OpenClaw. Не используйте sudo ради плагина.

Нужны Bash, Node.js, npm, sha256sum (Linux) либо shasum (macOS) и уже установленный OpenClaw. Для Windows используйте поддерживаемое окружение Linux/WSL. Манифест плагина объявляет OpenClaw >=2026.8.1, но это не доказательство совместимости со всеми последующими версиями. Релиз 0.8.2 подготовлен из публичного дистрибутива runtime 0.8.1; кроме константы версии исполняемый код не менялся; команды сверены с документацией OpenClaw 2026.10.5. Установщик использует Node-базу этого OpenClaw: 24.16+ в ветке 24.x или 26.1+ в ветке 26.x. Дополнительно соблюдайте engines своей версии OpenClaw. На реальном целевом сервере установка этим релизом не проверялась.

```bash
node --version
npm --version
openclaw --version
```

Если `openclaw: command not found`, сначала установите OpenClaw по официальной инструкции https://docs.openclaw.ai/install или исправьте PATH в своей оболочке. Плагин не устанавливает OpenClaw и не обновляет его. Если CLI уже установлен вне PATH, используйте `--openclaw-bin /полный/путь/openclaw`. Аналогично поддерживается переменная `OPENCLAW_BIN`.

Перед заменой существующей версии сохраните свою конфигурацию OpenClaw (с учётом профиля, include-файлов и SecretRef) и текущий каталог плагина в приватную резервную копию. Не прикладывайте эту копию к GitHub. Установщик не читает секреты и сам не создаёт резервную копию конфигурации.

## 2. Распаковать и установить

Скачайте `access-broker-v0.8.2-installation.zip` из доверенного GitHub Release и распакуйте штатным архиватором. Выбирайте именно этот asset, не старые Source code архивы v0.8.1: они неполные. Откройте терминал в родительском каталоге распакованной папки:

```bash
cd access-broker-v0.8.2-installation
bash install.sh --dry-run
bash install.sh
```

Из полного клона main (после публикации полного коммита v0.8.2):

```bash
git clone https://github.com/NosDorma-pixel/openclaw-access-broker.git
cd openclaw-access-broker
bash install.sh --dry-run
bash install.sh
```

Имя папки из GitHub Source code ZIP отличается: войдите в фактически распакованную папку с install.sh. Скрипт ищет TGZ и SHA256SUMS относительно своего расположения, не текущего каталога shell. Не используйте неполный старый тег v0.8.1.

Для нестандартного расположения CLI:

```bash
bash install.sh --openclaw-bin /полный/путь/openclaw --dry-run
bash install.sh --openclaw-bin /полный/путь/openclaw
```

Установщик проверяет SHA-256 всех файлов дистрибутива и вызывает ровно `openclaw plugins install npm-pack:<абсолютный-путь-к-tgz>`. Сам установщик не переписывает конфигурацию; **CLI OpenClaw может записать установочные записи/политику и активировать плагин**. Проверка SHA-256 обнаруживает повреждение, но не доказывает авторство: скачивайте релиз из доверенного источника. Не меняйте файлы до установки, иначе проверка не пройдёт.

Просмотрите и подтвердите запрошенное доверие источнику и capabilities. Установщик не передаёт `--accept-capabilities` и не обходит install policy. При неинтерактивном запуске OpenClaw может остановиться до подтверждения доверия. Только после осознанной проверки источника и резервного копирования:

```bash
bash install.sh --force
```

**`--force` одновременно подтверждает источник и разрешает перезапись существующей установки. По умолчанию флага нет.** Штатный OpenClaw без него отклоняет замену существующего плагина; установщик не удаляет старый каталог. Если CLI сообщает об отказе политики, consent или несовместимости, устраните названную причину; не отключайте проверки вслепую.

Вместо скрипта из корня полного дистрибутива или клона (сначала проверьте sha256sum --check SHA256SUMS):

```bash
openclaw plugins install npm-pack:./releases/local-openclaw-ssh-broker-0.8.2.tgz
```

## 3. Настроить HTTPS и Telegram

Эти шаги зависят от вашего домена/хостинга и не автоматизированы.

1. Настройте Telegram-канал средствами OpenClaw; bot token вводите только в защищённом канальном установщике, не в репозиторий/чат/аргументы shell. Разрешите владельцу команду `/accesslogin` с правом `operator.admin`. Для настройки используйте официальный раздел https://docs.openclaw.ai/channels/telegram .
2. Создайте DNS-запись для собственного `access.example.com`, выпустите действительный TLS-сертификат и настройте доверенный reverse proxy до HTTP listener вашего Gateway. Его адрес/порт берите из своей конфигурации, а не копируйте чужие. У плагина нет отдельного HTTP-порта: он регистрирует `/access-broker/credential/` и `/access-broker/ssh/` в Gateway.
3. Прокси должен сохранять пути, методы, тело формы и корректный внешний HTTPS origin. Не переписывайте Origin на произвольное значение. Согласуйте доверенные прокси с документацией OpenClaw. Не журналируйте URL с билетами, POST-тела и cookies. Оставьте аутентификацию остальных маршрутов Gateway включённой; при проксировании всего listener наружу оцените все доступные маршруты.
4. В интерфейсе настройки OpenClaw объедините значение из `examples/plugin-config.json` с **`plugins.entries["ssh-broker"].config`**. Замените домен своим. Это фрагмент, не полный openclaw.json; не перезаписывайте конфигурацию целиком.

Альтернатива для временного использования — отдельно установленный cloudflared и `examples/plugin-config-quick-tunnel.json`. Замените абсолютный путь executable своим и не задавайте одновременно демонстрационный publicBaseUrl. Бинарник cloudflared не включён. Quick Tunnel публикует HTTP listener Gateway целиком, а не только форму; заранее проверьте его авторизацию. Постоянный HTTPS-домен рекомендуется для регулярного использования.

Telegram Web App здесь — способ открыть форму. Плагин не проверяет Telegram initData: авторизация формы основана на криптографическом билете, CSRF nonce и Origin. Ссылку формы нельзя пересылать или публиковать.

## 4. Разрешить только нужные инструменты

Все 18 tools optional. `examples/tool-policy-fragment.json` показывает только фрагмент глобального `tools`; объедините его с действующей политикой, не удаляя allow/deny, профили, запреты и ограничения агента. Пример разрешает только список подключений, чтение SSH и удаление доступа. deny имеет приоритет; при агентных профилях может требоваться настройка именно целевого агента. Остальные имена перечислены в `openclaw.plugin.json` → contracts.tools.

Для API отдельно разрешаются нужные `access_broker_*`; для модификации файлов — конкретные инструменты записи. `ssh_broker_exec` включайте только при необходимости: нужны и tool policy, и отдельный флажок согласия владельца в форме. **allowedRoots ограничивает SFTP, но не является sandbox для shell-команд.** Используйте отдельного непривилегированного SSH-пользователя.

## 5. Включить и проверить

```bash
openclaw plugins enable ssh-broker
openclaw plugins list --json
openclaw plugins inspect ssh-broker --runtime --json
```

Если OpenClaw требует capability consent, внимательно просмотрите запрос. Следуйте сообщениям своей версии CLI. Установщик не перезапускает Gateway. Современный OpenClaw может применить установку через работающий Gateway; если ваша версия требует reload/restart, выполните это самостоятельно через интерфейс управления OpenClaw. Не перезапускайте работающие задачи без подготовки: временные credentials могут потеряться.

Один функциональный сценарий после настройки: в личном Telegram-чате отправьте `/accesslogin`, откройте форму, передайте тестовый SSH-доступ к отдельному непривилегированному пользователю и ограниченному каталогу, независимо сверьте fingerprint, попросите показать список каталога, затем удалить временный доступ. Не вводите пароли в чат. Это проверка на вашем хосте; поставляемый архив прошёл только изолированную проверку упаковки/установщика с заглушкой CLI, не реальную установку или сетевой вход.

## Обновление, откат и публикация

Перед обновлением сохраняйте приватную резервную копию. Для намеренной переустановки локального архива используйте `--force` после проверки; для отслеживаемого источника смотрите `openclaw plugins update` своей версии. При откате устанавливайте ранее сохранённый доверенный .tgz и восстанавливайте только относящиеся к плагину настройки, не всю устаревшую конфигурацию поверх новой. Пароли повторно передавайте через новую форму.

Для GitHub сначала загрузите ВСЁ содержимое этой папки в корень main, включая скрытый .gitignore, LICENSE, обновлённые README.md/INSTALL.md/install.sh, SHA256SUMS и все папки; закоммитьте изменения. Только ПОСЛЕ коммита создайте новый тег v0.8.2 на актуальном main и релиз Access Broker v0.8.2; приложите installation.zip и при желании отдельный .tgz. Старый тег v0.8.1 не перемещайте. Старый releases/*0.8.1.tgz может остаться как неиспользуемый файл и не требуется текущему установщику. Здесь ничего не опубликовано автоматически. `package.json` сохраняет `private: true`, поэтому это не публикация в npm.
